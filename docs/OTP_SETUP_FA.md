# ورود پیامکی با ملی‌پیامک

شماره ثبت‌شده حساب وارد می‌شود، کد ۶ رقمی ارسال می‌شود و پس از تأیید، کاربر به پنل نقش خودش وارد می‌شود. ثبت‌نام حساب جدید، قوانین نقش‌ها و ورود با رمز تغییر نکرده‌اند؛ ورود با رمز برای حساب‌های بدون شماره و خطای سرویس در دسترس است.

## تنظیم روی چابکان

ابتدا بکاپ بگیرید. متغیرها را در محیط سرور تنظیم کنید؛ فایل .env یا رمز وب‌سرویس را در GitHub یا چت قرار ندهید:

```dotenv
OTP_LOGIN_ENABLED=True
MELIPAYAMAK_USERNAME=نام_کاربری_وب_سرویس
MELIPAYAMAK_PASSWORD=رمز_وب_سرویس
MELIPAYAMAK_SENDER=شماره_خط_ارسال
MELIPAYAMAK_OTP_BODY_ID=
```

دو روش ارسال:

- الگوی خدماتی تأییدشده: شناسه Body ID را در MELIPAYAMAK_OTP_BODY_ID قرار دهید. الگو باید فقط یک پارامتر داشته باشد، یعنی کد ۶ رقمی. در این حالت خط فرستنده الزامی نیست.
- پیامک معمولی: Body ID خالی بماند و MELIPAYAMAK_SENDER تنظیم شود. تحویل به شماره‌های مسدودکننده پیامک تبلیغاتی به نوع خط و مجوز پنل بستگی دارد.

صرف داشتن پنل به معنی فعال بودن وب‌سرویس، تأیید الگو یا داشتن اعتبار ارسال نیست. اعتبار، مجوز و الگو را در پنل ملی‌پیامک بررسی کنید. پاسخ پذیرش ارسال بررسی می‌شود؛ تأیید تحویل واقعی به گوشی نیازمند آزمون با حساب خودتان است.

پس از دریافت کد:

```bash
python manage.py migrate
python manage.py collectstatic --noinput
python manage.py check_otp_phones
```

سپس برنامه را ری‌استارت کنید. بررسی شماره‌ها را قبل از انتشار عمومی انجام دهید؛ برای مدیر هم یک شماره معتبر ثبت کنید. کدهای این تغییر یک migration جدید دارند و بدون migrate نباید منتشر شوند.

شماره‌های قبلی هنگام migration یکسان‌سازی می‌شوند. هر شماره باید فقط به یک حساب متصل باشد؛ اشتراک شماره بین مدیر/مربی/شاگرد پشتیبانی نمی‌شود تا نقش اشتباهی باز نشود. شماره اصلی کاربر حذف یا بازنویسی نمی‌شود. شماره خالی، نامعتبر، تکراری یا حساب غیرفعال هیچ پیامکی دریافت نمی‌کند. فرم جزئیات وجود حساب‌ها را آشکار نمی‌کند؛ در این موارد از ورود با رمز و ویرایش حساب توسط مدیر استفاده کنید.

## محدودیت‌ها

- اعتبار کد: ۳ دقیقه؛ یک‌بارمصرف و متصل به مرورگر درخواست‌کننده.
- حداکثر ۵ تلاش برای هر کد؛ کد اشتباه یا منقضی وارد نمی‌کند.
- فاصله ارسال: ۶۰ ثانیه؛ حداکثر ۳ درخواست برای شماره و ۱۰ درخواست برای IP در بازه ۱۵ دقیقه‌ای.
- ارسال مجدد، کد قبلی را نامعتبر می‌کند. شماره، فعال بودن و یکتایی حساب هنگام تأیید دوباره بررسی می‌شوند.
- کد خام در دیتابیس، لاگ، پاسخ صفحه یا نشست ذخیره نمی‌شود.
- با اجرای روزانه cleanup_old_data رکوردهای قدیمی OTP هم پاک می‌شوند.
- پیش‌فرض محدودیت IP بر اساس REMOTE_ADDR است. پشت پراکسی ممکن است چند کاربر یک IP داشته باشند. فقط پس از اطمینان از بازنویسی X-Forwarded-For توسط میزبان، OTP_TRUST_X_FORWARDED_FOR=True شود.

## نسخه آزمایشی Render

نسخه آزمایشی، ارسال پیامک واقعی را به‌طور عمدی خاموش نگه می‌دارد و کاربران نمونه شماره واقعی ندارند؛ از پیوند «ورود با نام کاربری و رمز عبور» استفاده کنید. اتصال SMS در نسخه اصلی چابکان از تنظیمات بالا استفاده می‌کند. برای فعال‌سازی واقعی روی محیط آزمایشی باید جداگانه تنظیمات مخصوص آن محیط بازبینی شوند.

آزمون خودکار از سرویس ساختگی استفاده می‌کند و SMS واقعی ارسال نمی‌کند. برای پذیرش نهایی، پس از تنظیم سرور یک کد واقعی دریافت و ورود هر سه نقش با شماره‌های مجزا بررسی شود.
